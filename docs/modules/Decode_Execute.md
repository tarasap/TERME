# Decode/Execute Unit (DEX Stage)

## Overview

The `Decode_Execute` module implements the Decode/Execute stage of the
TERME processor pipeline.

TERME uses a three-stage in-order pipeline:
    Fetch              Decode/Execute          Memory/Write-Back

      F  ---------------- DEX ---------------- MWB

The Decode/Execute stage receives the fetched instruction from the Fetch
stage and generates the execution results required by later pipeline
stages.

The module is responsible for integrating:

- Instruction field extraction
- Register file access
- Immediate generation
- Operand selection
- ALU execution
- Branch decision generation
- Multiplication unit interface
- Forwarding support

---
## Module Interface

The `Decode_Execute` interface is divided into three groups: clock and
reset, control signals, and data signals.

### Clock and Reset

| Port | Direction | Width | Description |
|---|---|---:|---|
| `clk` | Input | 1 | System clock |
| `rst` | Input | 1 | Reset signal |

### Control Signals

| Port | Direction | Width | Description |
|---|---|---:|---|
| `Immediate_Type_i` | Input | 3 | Selects the immediate type |
| `Regread_i` | Input | 1 | Register-file read control |
| `ImmEnable_i` | Input | 1 | Immediate generation control |
| `ResultSrc_i` | Input | 2 | Result source control |
| `ALUSrc_i` | Input | 2 | ALU source selection control |
| `ALUControl_i` | Input | 5 | ALU operation control |
| `ForwardA_i` | Input | 2 | Forwarding selection for operand A path |
| `ForwardB_i` | Input | 2 | Forwarding selection for operand B path |
| `Jump_i` | Input | 1 | Jump control signal |
| `Regwrite_mwb_i` | Input | 1 | Register write control from the MWB stage |
| `BrchEnable_i` | Input | 1 | Branch enable control |
| `Mul_Start_i` | Input | 1 | Multiplication start control |
| `Mul_Hi_i` | Input | 1 | Multiplication result selection control |
| `Mul_Signa_i` | Input | 1 | Signedness control for multiplication operand A |
| `Mul_Signb_i` | Input | 1 | Signedness control for multiplication operand B |
| `PCSrc_dex_o` | Output | 1 | PC source/redirection control generated by the DEX stage |
| `Mul_Busy_dex_o` | Output | 1 | Multiplication busy status |
| `Mul_Done_dex_o` | Output | 1 | Multiplication completion status |

### Data Signals

| Port | Direction | Width | Description |
|---|---|---:|---|
| `PC_Out_i` | Input | `size` | Current PC value |
| `PC_Plus_i` | Input | `size` | Incremented PC value |
| `Instruction_i` | Input | `size` | Instruction received by the DEX stage |
| `Rd_mwb_i` | Input | 5 | Destination register index from the MWB stage |
| `Writeback_Result_i` | Input | `size` | Write-back result from the MWB stage |
| `Rs1_dex_o` | Output | 5 | `rs1` field extracted from the instruction |
| `Rs2_dex_o` | Output | 5 | `rs2` field extracted from the instruction |
| `Rd_dex_o` | Output | 5 | `rd` field extracted from the instruction |
| `OPCode_dex_o` | Output | 7 | Opcode field extracted from `Instruction_i[6:0]` |
| `Funct3_dex_o` | Output | 3 | `funct3` field extracted from `Instruction_i[14:12]` |
| `Funct7_dex_o` | Output | 7 | `funct7` field extracted from `Instruction_i[31:25]` |
| `Funct12_dex_o` | Output | 12 | 12-bit field extracted from `Instruction_i[31:20]` |
| `OPB5_dex_o` | Output | 1 | Bit 5 of the instruction |
| `Sign_Extended_dex_o` | Output | `size` | Output of the sign-extension path |
| `Alu_Result_dex_o` | Output | `size` | Result produced by the ALU lane |
| `SrcB_dex_o` | Output | `size` | Source B value from the ALU lane |
| `SrcA_dex_o` | Output | `size` | Source A value from the ALU lane |
| `Mul_Result_dex_o` | Output | `size` | Result produced by the multiplication unit |

# Internal Structure

The Decode_Execute module connects several execution-related blocks:

| Instance | Module | Purpose |
|---|---|---|
| `RF_dex` | `Regfile` | Register-file interface |
| `SE_dex` | `Sign_Extension` | Immediate generation |
| `BJU_dex` | `Branch_Unit` | Branch decision generation |
| `AL_dex` | `ALU_Lane` | Operand processing and ALU execution |
| `MUL_dex` | `Mul_Unit` | Multiplication operations |

The detailed behavior of each submodule is documented separately.
