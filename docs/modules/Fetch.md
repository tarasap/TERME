# Fetch Unit (F-Stage)

## Overview

The `Fetch` module implements the instruction fetch stage of the TERME
processor pipeline.

TERME uses a three-stage in-order pipeline:
    Fetch              Decode/Execute          Memory/Write-Back

      F  ---------------- DEX ---------------- MWB


The Fetch stage is responsible for obtaining instructions from instruction
memory, maintaining the program counter (PC), handling control-flow
changes, and supporting RISC-V compressed instructions.

Main responsibilities:

- Program counter generation and update
- Instruction memory request generation
- Instruction fetch stall handling
- Branch and jump redirection
- Interrupt and exception redirection
- `MRET` return handling
- RV32C compressed instruction detection and decompression

The fetched instruction is forwarded to the Decode/Execute stage for
instruction decoding and execution.

# Module Interface

## Clock and Reset

| Port | Direction | Width | Description |
|---|---|---|---|
| `clk` | Input | 1 | System clock |
| `rst` | Input | 1 | Processor reset signal |

---

## Control Inputs

| Port | Direction | Width | Description |
|---|---|---:|---|
| `Irq_Taken_i` | Input | 1 | Indicates an accepted interrupt and redirects execution to the trap handler |
| `Mret_i` | Input | 1 | Indicates execution of the RISC-V `MRET` instruction |
| `PCSrc_dex_i` | Input | 1 | Indicates a branch/jump redirection request from the Decode/Execute stage |
| `StallF_i` | Input | 1 | Stops PC advancement during pipeline stalls |
| `Trap_Next_PC_i` | Input | 32 | Trap handler address used during interrupt/exception entry |
| `PC_Target_i` | Input | 32 | Target address generated by branch or jump instructions |

---

## Instruction Memory Interface

| Port | Direction | Width | Description |
|---|---|---:|---|
| `Imem_Valid_i` | Input | 1 | Indicates valid instruction data returned from instruction memory |
| `Imem_Data_i` | Input | 32 | Instruction data received from instruction memory |
| `Imem_Req_fe_o` | Output | 1 | Instruction memory request signal |
| `Imem_Stall_fe_o` | Output | 1 | Indicates instruction fetch is stalled |

---

## Fetch Stage Outputs

| Port | Direction | Width | Description |
|---|---|---:|---|
| `PC_Out_fe_o` | Output | 32 | Current instruction address |
| `PC_Plus_fe_o` | Output | 32 | Next sequential PC address |
| `Instruction_fe_o` | Output | 32 | Final 32-bit instruction after optional decompression |
| `OPCode_fe_o` | Output | 7 | RISC-V opcode field extracted from the instruction |

---

# Internal Architecture

The Fetch module consists of four main components:

| Component | Description |
|---|---|
| Program Counter Register | Stores the current instruction address |
| Instruction Load Unit (ILU) | Handles instruction memory transactions |
| Decompressor | Expands RV32C compressed instructions into RV32I format |
| Instruction Multiplexer | Selects between normal and decompressed instructions |
